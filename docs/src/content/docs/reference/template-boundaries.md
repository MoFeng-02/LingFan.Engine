description: 脚手架自带宿主接了哪些能力、哪些没接、哪些在这套形态里根本不适用，以及没接的部分会看到什么。
---

脚手架自带的宿主是能跑的最小实现。它把每个等待态都留了出口，但没有把引擎的能力全接一遍。

判断标准只有一条：**故事不能卡死**。引擎能进入的每个等待态，模板都必须给玩家一个能推进的按钮。做不到这一条的能力，宁可显式报「未注册」，也不装作做完了。

`project.json` 里的 `shell.*` 是另一回事——它必须真的被读。你改了 `shell.saves.slots`，存档下拉里的槽位就得跟着变；改了没效果比不支持更难查。

## 接了

| 能力                                      | 落点                                                |
| ----------------------------------------- | --------------------------------------------------- |
| 对话层：打字机 + 内联标记                 | `say` 的逐字显示、`{p}` `{w}` 停顿、样式标记        |
| 等待态出口：`menu` `input` `wait` `video` | 四个都能推进                                        |
| 等待态：`minigame`                        | 显示「未注册」并说明怎么接，不伪造完成              |
| 舞台元素层                                | 36 种元素类型、元素交互、12 条表现指令              |
| 层级 z 序                                 | `shell.layers` 解析后写进 DOM                       |
| 存档                                      | `shell.saves.slots` 决定槽位数，存 / 读走引擎命令面 |

对话层那条值得说清楚：`{p}` `{w}` 的停顿、样式标记的零宽处理都在展示层做，引擎只负责把带标记的文本放进状态。所以你在 `say` 里写 `{b}加粗{/b}` 能看到效果，但那是模板的对话渲染器在解析，不是引擎。

`animate` / `transition` / `shake` 三个是**帧驱动**的——模板每帧读一次动画队列，插值后写进 DOM，播完回调写回终值。不驱动的话动画队列只增不减，元素永远停在起点。这三个在模板里是接了的。

元素命令走注册表。故事里给元素写 `cmd="..."`，宿主去注册表查这个名字；查不到就报「元素命令未注册」，不静默跳过。同理，元素类型没注册会报「元素类型未注册」。作者写了却看不见效果，比报一行错难查得多。

## 没接

这些是**模板宿主没接线**，不是引擎没有这个能力：

| 能力                           | 没接的表现                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------- |
| 存档缩略图                     | 存出来的档没有截图                                                                     |
| 历史面板与回溯 UI              | 玩家界面上没有回退按钮                                                                 |
| 玩家偏好面板（音量、文字速度） | 音量就是指令里写的值，打字机取故事级 `text_typewriter`                                 |
| I18N 供给                      | `Lang/` 目录完全不参与，原文直出                                                       |
| 对话框模板注册                 | `say template=` 写了也没用，走内建骨架                                                 |
| 资源加密                       | 清单里写了 `resourceEncryption` 也不生效，模板按静态根直读                             |
| 舞台适配（`shell.stage`）      | 模板宿主按固定视口布局，基准与缩放不生效；要接就取 `resolveStageConfig` 的结果再算变换 |
| 热重载                         | 改了故事文件不会就地重载，只能整页刷新                                                 |
| 宿主信息                       | 模板没调用 `HostPort`，按端分支没有落点                                                |

**存档缩略图**：引擎的存档载荷里有 `screenshot` 字段（data URL，由宿主合成），模板不传。不传就是一张没有图的存档，不是坏档。

**历史面板与回溯 UI**：引擎有 `historyView()`、`rollbackTo()`、`back()`、`forward()`，模板没做界面。你在控制台调这些方法能看到效果，但页面上没有入口。

**玩家偏好**：引擎接受偏好注入，优先级高于故事级设置。模板没接，所以 `text_typewriter speed=30` 就是最终速度，没有玩家面板能覆盖它。

**I18N 供给**：引擎的 `i18nPort` 缺省语义就是原文直出。模板没接端口，所以 `Resources/Lang/` 下的译文表不会被加载——不是加载失败，是根本没去读。想看到译文得自己接。

**对话框模板**：`say template="xxx"` 走的是模板注册表。模板没注册任何模板，`template=` 会被忽略，显示的还是内建骨架。

**资源加密**：引擎侧的接口是 `ResourcePort`——给一个逻辑路径，还一个当前能用的地址。静态根直接拼路径，加密形态解密后给一个短生命周期地址，两种实现接的是同一个接口。模板用的是静态根那份。这不代表网页里做不了加密：取回密文、在页面里解出明文、造一个临时地址交给 `resolve()`，路径是通的。模板没做，是宿主代码里没写这段。

**热重载**：引擎有 `reloadStory()`，能把故事定义原子换掉并保留变量与历史。缺的是「知道文件什么时候变了」——浏览器没有递归监视文件系统的能力，模板也就没接。桌面形态靠原生层监视源目录，触发后重新组装再喂给引擎。

**宿主信息**：`HostPort` 是一个只读事实（系统 + 形态），用来做按端分支。模板没调用它，所以里面没有按端行为。这个端口在网页里也能用——拿不到编译期平台时归 `unknown`，是显式未知，不是报错。

引擎侧这些能力都具备，`apps/playground` 里都有实现。模板和 playground 共用同一套引擎与适配器，差别只在宿主代码。

## 不适用

这一条不是「没接」，是在纯 Web 形态里没有对应的东西：

**屏幕方向锁定**（`shell.orientation`）。浏览器里没有锁定屏幕方向的 API。这个配置只在桌面壳（Tauri）里生效。在网页里写了它，什么也不会发生——不是被忽略，是平台层面没有可调用的东西。

## 换成你自己的宿主

模板的宿主不依赖任何 UI 框架——直接操作 DOM。换成 Vue、React 或者别的都行，引擎和适配器零改动。

接口本来就在那一层：宿主订阅引擎的状态变更，把变更落到自己的视图上；引擎不知道视图是什么。模板里那张订阅键表只有九个：

```text
currentDialogSpeaker  currentDialogText  waiting
nvlMode  nvlBuffer
menuOptions  menuTargets
dialogVisible  elements
```

你换框架时，要做的事情就是把这张表里的键接到自己的组件上，再订阅出站事件（引擎错误、`notify` 提示、小游戏挂载、存档回执）。其余部分——故事怎么解析、状态怎么存、回溯怎么重建——都在引擎里，跟你用什么框架无关。

具体怎么生成一个新工程、怎么装依赖，见[从模板创建工程](/from-template/)。

## 模板版本

模板版本记在 `template/v1/template-meta.json` 里，当前 `1.2.0`，要求的引擎版本是 `0.1.0`。

它和引擎版本**是两条线**。引擎发新版不会自动抬高模板版本——只有当模板内容真的变了才手动改这个数。所以你看到引擎是 0.3.0、模板还写着 1.2.0 是正常的。

引擎包以 TS 源码出口发布（`exports: "./src/index.ts"`），消费方由 Vite 和 TypeScript 直接编译，没有中间构建步骤。它们都在 registry 上，`pnpm install` 直接可用。
