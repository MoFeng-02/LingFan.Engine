import OpCard from "../../../../components/OpCard.astro";

音频走四条通道：`bgm`、`ambient`、`voice` 是常驻通道，`se` 是一次性触发。引擎只往状态里写通道对象，真正的播放由宿主落地——所以这些指令执行完立刻往下走，不等声音播完。

路径相对资源根写：`bgm "Audio/main.mp3"` 指的是 `Resources/Audio/main.mp3`。

## 指令

### bgm

<OpCard name="bgm" summary="播放背景乐，写常驻通道。" rollback="full" since="0.1.0">

**签名**

```text
bgm "Audio/main.mp3"
bgm "Audio/rain.mp3" volume=0.6 fade=800
bgm "Audio/theme.mp3" restart
```

**参数**

| 字段       | 类型    | 说明                                  |
| ---------- | ------- | ------------------------------------- |
| `resource` | string  | 必填。相对资源根的路径                |
| `volume`   | number  | 可选，缺省 1。越界钳到 0..1           |
| `loop`     | boolean | 可选，缺省 `true`                     |
| `fade`     | number  | 可选，缺省 0。毫秒                    |
| `restart`  | boolean | 可选。文本形态里裸写 `restart` 即为真 |

**最小示例**

```text
label chapter_one:
  bgm "Audio/main.mp3" fade=1200
  say "雨点打在铁皮上。"
  bgm "Audio/rain.mp3" volume=0.5
```

**常见错误**

:::caution
播放位置只在三种情况下归零：第一次播、换了一首、显式 `restart`。**同一首再写一遍不会重头播**，音量变了就只改音量。这条是为了让回滚和读档不打断正在放的曲子——引擎重放这条命令时，位置还接着原来的走。

想要「同一首从头再来一遍」就写 `restart`。它会把序号加一，宿主据此收到一次独立的重播事件；连续两次 `restart` 也是两次事件，不会被合并。

`volume` 写非有限数字（`NaN`、`Infinity`）报 `bgm-invalid-volume`；`fade` 写负数报 `bgm-invalid-fade`。越界的音量会被钳到 0..1，但越界不会报错——`volume=2` 是静默变成 1。

路径写空串报 `bgm-invalid-resource`。
:::

</OpCard>

### se

<OpCard name="se" summary="播一次性音效，每次执行都触发。" rollback="full" since="0.1.0">

**签名**

```text
se "Audio/click.mp3"
se "Audio/thunder.mp3" volume=0.8
```

**参数**

| 字段       | 类型   | 说明         |
| ---------- | ------ | ------------ |
| `resource` | string | 必填         |
| `volume`   | number | 可选，缺省 1 |

**最小示例**

```text
se "Audio/thunder.mp3"
say "一道闪电把屋子照亮。"
```

**常见错误**

:::caution
`se` 没有 `loop`、`fade`、`restart`，写了报 `se 未知负载字段`。文本形态里写 `se "…" restart` 会直接拒绝整个文件，报「se 不支持 restart（一次性音效恒重播）」。

它靠单调递增的序号判定，所以**同一条 `se` 连续执行两次就是两声**，不会像 `bgm` 那样被当成「同一首，跳过」。反过来，回溯到 `se` 之前再往前走，也会再响一次——它是重放出来的，引擎没法让已经响过的声音「没响过」。
:::

</OpCard>

### ambient

<OpCard name="ambient" summary="播放环境音，独立于背景乐。" rollback="full" since="0.1.0">

**签名**

```text
ambient "Audio/wind.mp3" volume=0.4
stop_ambient fade=600
```

**参数**

字段和 `bgm` 完全一致：`resource`、`volume`、`loop`、`fade`、`restart`。`loop` 同样缺省 `true`。

**最小示例**

```text
bgm "Audio/main.mp3"
ambient "Audio/wind.mp3" volume=0.3 fade=2000
say "风从山口灌下来。"
```

**常见错误**

:::caution
`ambient` 是独立通道，不是 `bgm` 的第二个音量层。想「压低背景乐突出环境音」得自己写两个 `bgm` / `ambient` 命令分别调音量，引擎不会替你把它们混在一起算。

和 `bgm` 一样，同一首再写一遍只更新参数，不重头播。想要重播加 `restart`。

环境音**不会因为换场景自动停**。离开一个场景要显式 `stop_ambient`，否则它会一直响到故事结束或者被下一条 `ambient` 换掉。
:::

</OpCard>

### voice

<OpCard name="voice" summary="播放语音，常驻通道。" rollback="full" since="0.1.0">

**签名**

```text
voice "Audio/ache_01.mp3"
voice "Audio/ache_02.mp3" volume=0.9 auto_stop=false
```

**参数**

| 字段        | 类型    | 说明              |
| ----------- | ------- | ----------------- |
| `resource`  | string  | 必填              |
| `volume`    | number  | 可选，缺省 1      |
| `auto_stop` | boolean | 可选，缺省 `true` |
| `restart`   | boolean | 可选              |

**最小示例**

```text
voice "Audio/ache_01.mp3"
say "「别站在雨里。」" speaker="阿澈"
```

**常见错误**

:::caution
`voice` **不接受 `loop`**，写 `loop=true` 报未知字段——语音恒不循环。想让它多放几遍就写多条 `voice`。

`auto_stop` 缺省为真，意思是：这句对话被玩家推进过去时，语音自动停。把它设成 `false`，语音会一直放下去，直到下一条 `voice` 或 `stop_voice`。

`say voice="…"` 是另一条路——它把语音绑在这一句对话上，效果和「先 `voice` 再 `say`」一样，但少写一条命令。用哪个都行，别同一条对话两边都写。
:::

</OpCard>

### stop_bgm

<OpCard name="stop_bgm" summary="停止背景乐。" rollback="full" since="0.1.0">

**签名**

```text
stop_bgm
stop_bgm fade=1500
```

**参数**

| 字段   | 类型   | 说明               |
| ------ | ------ | ------------------ |
| `fade` | number | 可选，缺省 0。毫秒 |

**最小示例**

```text
say "门在身后关上。"
stop_bgm fade=2000
```

**常见错误**

:::caution
`stop_bgm` 把通道写成停止形态，并且**把播放位置归零**。这意味着之后重新 `bgm` 同一首会从头播——即使不写 `restart`。

它只认 `fade` 一个参数，写别的报「stop_bgm 未知负载字段」。想改音量用 `bgm` 重写一遍，不是 `stop_bgm`。

`fade` 是淡出时长，命令本身不等它。写 `stop_bgm fade=3000` 之后下一句 `say` 会立刻显示，背景乐在背后慢慢淡掉。
:::

</OpCard>

### stop_ambient

<OpCard name="stop_ambient" summary="停止环境音。" rollback="full" since="0.1.0">

**签名**

```text
stop_ambient
stop_ambient fade=800
```

**参数**

| 字段   | 类型   | 说明               |
| ------ | ------ | ------------------ |
| `fade` | number | 可选，缺省 0。毫秒 |

**最小示例**

```text
stop_ambient fade=800
bgm "Audio/indoor.mp3"
```

**常见错误**

:::caution
和 `stop_bgm` 不同，`stop_ambient` **不动播放位置**——`ambient` 没有位置归零的逻辑，所以停掉之后再放同一首是重新开始还是接着放，取决于宿主怎么实现。要确定的行为就换一首或者显式写 `restart`。

只认 `fade`，写别的报「stop_ambient 未知负载字段」。
:::

</OpCard>

### stop_voice

<OpCard name="stop_voice" summary="停止语音通道。" rollback="full" since="0.1.0">

**签名**

```text
stop_voice
stop_voice fade=300
```

**参数**

| 字段   | 类型   | 说明               |
| ------ | ------ | ------------------ |
| `fade` | number | 可选，缺省 0。毫秒 |

**最小示例**

```text
say "「……算了。」" speaker="阿澈"
stop_voice
```

**常见错误**

:::caution
只认 `fade`，写别的报「stop_voice 未知负载字段」。

语音通常靠 `auto_stop` 自动收尾，所以 `stop_voice` 更多用在「玩家点得比语音快，得让它立刻断掉」这种场合。淡出时长写太大会和下一句语音叠在一起。
:::

</OpCard>

### stop_se

<OpCard name="stop_se" summary="停掉正在响的一次性音效。" rollback="full" since="0.3.0">

**签名**

```text
stop_se
stop_se fade=200
```

**参数**

| 字段   | 类型   | 说明               |
| ------ | ------ | ------------------ |
| `fade` | number | 可选，缺省 0。毫秒 |

**最小示例**

```text
se "Audio/alarm.mp3" volume=0.7
say "警报响了很久。"
stop_se fade=400
say "终于有人把它关掉。"
```

**常见错误**

:::caution
只认 `fade`，写别的报「stop_se 未知负载字段」。

`se` 是一次性音效：同一条命令连写两次就是两声，各自独立叠放。所以 `stop_se` 停的是**此刻还在响的所有音效**，它没有「停哪一个」的概念——这与 `stop_bgm` / `stop_ambient` / `stop_voice` 停各自那条常驻通道的语义一致，只是 `se` 那条「通道」本来就能同时响很多声。

音效没有位置回写，`stop_se` 也不影响背景乐的播放位置。
:::

</OpCard>

### audio_play

<OpCard name="audio_play" summary="按名字起播（或更新）一条独立的音轨。" rollback="full" since="0.3.0">

```text
audio_play <实例 id> <通道> "<资源>" [volume=0..1] [loop=true|false] [fade=毫秒] [restart=true|false]
```

**参数**

| 参数      | 类型    | 必填 | 说明                                                    |
| --------- | ------- | ---- | ------------------------------------------------------- |
| 实例 id   | text    | 是   | 小写字母开头的短 id（1..32 位，可含 `_` `-`）。         |
| 通道      | text    | 是   | `bgm` / `se` / `ambient` / `voice` 之一，决定偏好归口。 |
| 资源      | text    | 是   | 音频资源路径（相对 `Resources/`）。                     |
| `volume`  | number  | 否   | 0–1；不写则取工程默认，再没有就是 1。                   |
| `loop`    | boolean | 否   | 缺省 `true`（一直响到 `audio_stop`）。                  |
| `fade`    | number  | 否   | 淡入毫秒，缺省 0。                                      |
| `restart` | boolean | 否   | 显式从头重播（同资源时也重播）。                        |

**最小示例**

```text
audio_play rain ambient "Audio/rain.ogg" volume=0.3
audio_play steps se "Audio/steps.ogg" volume=0.7
say "雨声和脚步同时在响，互不影响。"
```

**常见错误**

:::caution
实例 id 与通道都是必填。id 写错形态（大写、数字开头、超 32 位、空串）会直接报错并指出期望形态——引擎不会替你猜一个名字。

同一实例重复 `audio_play`：

- 同资源 → **更新**（位置保留，音量/循环随新参数），不会重头播
- 换资源或 `restart=true` → 重播

同时存活的实例最多 32 个。超了报错并提示先 `audio_stop` 掉不用的实例——上限是为了让存档体积有界，不是省内存。
:::

</OpCard>

### audio_stop

<OpCard name="audio_stop" summary="停止一个音频实例，或停掉全部实例。" rollback="full" since="0.3.0">

```text
audio_stop [实例 id] [fade=毫秒]
```

**参数**

| 参数    | 类型   | 必填 | 说明                       |
| ------- | ------ | ---- | -------------------------- |
| 实例 id | text   | 否   | 省略 = 停掉当前全部实例。  |
| `fade`  | number | 否   | 淡出毫秒，缺省 0（立即）。 |

**最小示例**

```text
audio_play rain ambient "Audio/rain.ogg"
say "雨下起来了。"
audio_stop rain fade=800
say "雨停了。"
audio_stop
say "剩下的一切声音都停了。"
```

**常见错误**

:::caution
停一个不存在的实例会报错，并把当前有哪些实例列出来——静默成功会让作者以为写了但没生效。

没有实例可停时（`audio_stop` 且表为空）不算错：作者不必先判空。
:::

</OpCard>

### audio_volume

<OpCard name="audio_volume" summary="只改一个音频实例的音量，不重播、不动位置。" rollback="full" since="0.3.0">

```text
audio_volume <实例 id> volume=0..1
```

**参数**

| 参数     | 类型   | 必填 | 说明            |
| -------- | ------ | ---- | --------------- |
| 实例 id  | text   | 是   | 目标实例。      |
| `volume` | number | 是   | 0–1，越界钳制。 |

**最小示例**

```text
audio_play rain ambient "Audio/rain.ogg" volume=0.2
say "雨很小。"
audio_volume rain volume=0.9
say "雨大了起来——但曲子没有从头开始。"
```

**常见错误**

:::caution
这是「实时调音」的正规入口。**不要**用 `audio_play` 重发来改音量：那会重设播放位置并打断淡入。

给已停止的实例调音量会报错（先 `audio_play` 起播）；给不存在的实例调音量同样报错。
:::

</OpCard>

## 通道与实例

四通道（`bgm` / `se` / `ambient` / `voice`）和音频实例**并存**，不是两套实现：

- **通道**是叙事语义上的「那一路声音」——各一条，随存档与回溯走，是玩家偏好分档的依据。
- **实例**是作者点名的编排单元——数量不定、名字自起、各自独立叠放。

一个实例的状态里记着它归属哪条通道，玩家偏好就按那一条乘上去。所以雨声放在 `ambient` 通道，玩家把环境音量拉低，雨声跟着变小；放在 `bgm` 通道，就跟背景乐一起被调。

超时音效这类「响一下就完了」的东西用 `se` 就够；要同时留住好几条独立音轨、或者需要事后单独调某一条，才需要实例。

## 音量叠了三层

宿主侧算出来的实际音量是三个来源依次取第一个存在的：

1. **命令上的 `volume=`**——作者在这一条命令上的意图
2. **工程默认**（`project.json` 的 `shell.audio.volumes.<通道>`）——整部作品的口径
3. **1**——前两级都缺席时的兜底（与「不指定 = 满音量」的老行为逐字节一致）

然后再乘**玩家偏好**：玩家在设置面板把背景乐拉到 60%，那么 `bgm "…" volume=0.5` 实际响的是 0.3。

顺序不能反：偏好必须留在最外层。把工程默认塞进偏好层，就会变成「作者默认值污染玩家设置」——玩家换个作品，他的偏好不该被改。

## 换曲与不换曲

宿主收到的是状态差量，判定规则是：

- 通道从 `play` 变成 `stop` 或消失 → 停（带淡出参数）
- 资源变了 → 播
- 资源没变、序号变了（也就是写了 `restart`）→ 从头重播
- 资源没变、只有音量或 `loop` 变了 → 更新参数，**不重头播**

背景乐的位置回写有个 0.5 秒的阈值：宿主上报的位置和引擎记的位置差不到半秒，就当成播放器抖动，不触发定位。这条是为了避免每帧都去 seek 一下把曲子卡出杂音。
