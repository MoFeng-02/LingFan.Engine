内建指令 66 个，按用途分成 9 个域，每个域一页。这一页是入口：按名字找到指令，点进去看签名、参数和坑。

## 两种写法

同一条指令有两种写法，投影到同一份命令上：

- **文本形态**——写在 `.story` 文件里，一行一条，缩进表示块体。
- **JSON v1**——写在 `.json` 文件里，一条指令是一个对象。

一个工程里可以两种混放，引擎按文件内容判断用哪种解析。本页各域页的「签名」给的是文本形态，「参数」表列的是 JSON 字段名——两边一一对应，字段名就是文本形态里 `key=` 的那个 key。

```text
say "夜里十一点，雨还没停。" speaker="阿澈"
```

```json
{ "op": "say", "text": "夜里十一点，雨还没停。", "speaker": "阿澈" }
```

## 等待点

8 条指令会建立等待点。执行到它们，引擎停下来等玩家操作：

| 指令          | 等待态        | 怎么解除                            |
| ------------- | ------------- | ----------------------------------- |
| `say`         | `dialog`      | 玩家点击或按键                      |
| `menu`        | `menu`        | 玩家选中一项                        |
| `input`       | `input`       | 宿主回填输入                        |
| `wait`        | `wait`        | 计时到点；`skipable` 时也可点击解除 |
| `pause`       | `wait`        | 计时到点。`pause` 恒不可跳过        |
| `cutscene`    | `video`       | 播完；`skipable` 时也可点击解除     |
| `minigame`    | `minigame`    | 宿主回填结果                        |
| `interaction` | `interaction` | 宿主回填结果                        |

其余 58 条都不停，执行完就往下走。最容易记错的是 `video`——它开始播放就继续，要「播完再走」得用 `cutscene`。

等待点同时是检查点坐标。回退落回上一个等待点，读档也落在等待点上，所以等待点也就是存档点。

## 内建指令不能被覆盖

扩展 op 与内建重名，注册期直接抛错，整个工程装载失败：

```text
扩展 demo 的 op「say」与内建 op 冲突（内建不可覆盖）
```

查找顺序是内建 → 扩展 → 未知。自定义 op 覆盖不掉内建，写了也只会让工程打不开，不会悄悄接管。扩展 op 也不建立等待点，执行成功即步进。

细节见 [扩展引擎](/concepts/extensions/)。
