---
title: 跑某一列
description: 开发时直接跳到故事里的某一列：给开发命令带上列 id，跳过启动页进那一列，先看看这一段自己玩得通不通。
---

写故事最费时间的往往不是写，是「改一句 → 重启 → 走十分钟才走到那一句」。跑某一列这条通道就是为这件事准备的：给开发命令带上列 id，跳过启动页直接进那一列。

## 一条命令

在工程根跑：

```sh
pnpm dev --story-name inn
```

浏览器打开后直接就在 `inn` 这一列里。

（用别的包管理器就换一下写法，**npm 必须用 `--` 分隔**，否则它会把 `--story-name` 当成自己的选项吃掉：）

```sh
npm run dev -- --story-name inn
yarn dev --story-name inn
bun run dev --story-name inn
```

不带这个参数时行为完全不变，还是照常从启动页开始。

## 取值是列 id，不是文件名

`--story-name` 后面跟的是**列 id**，不是文件名。两者常常不一样：文件名是 `stage-demo.json` 的那一列，id 是 `stage_demo`（下划线，因为 id 是标识符不能用连字符）。列 id 在工程内唯一，可以跨文件。同一个文件里也可以有多列（文本形态的 `.story` 文件尤其常见），那时候文件名只跟首列对得上，其余列的 id 都得从文件里的列声明读。

拿不准有哪些列，就先列出来：

```sh
pnpm dev --list-entries
```

输出每行一个列 id 和它所在的文件：

```
inn	Stories/chapter1/inn.json
start	Stories/chapter1/start.json
square	Stories/chapter2/square.json
stage_demo	Stories/chapter2/stage-demo.json
```

列 id 在整个工程内唯一，同一个 id 出现在两个文件里属于事故，跑这一列时会直接报错并把两个候选文件都列出来，不会替你挑一个。

## 前提：故事产物是新的

这条通道读的是编译后的故事产物（`Resources/Stories/` 下的文件），不是源。改了源没重新编译，跑的还是旧内容。

```sh
pnpm stories:build
pnpm dev --story-name inn
```

产物目录空的时候，命令会告诉你「未找到故事文件」并给出目录路径；某个文件解析坏了，命令会带上那个文件的路径告诉你哪一份坏了——不会静默跳过。

## 会少掉什么

直达会先跑一遍入口列，然后跳到你指定的那一列。**入口列第一句台词及其之后的命令不会执行**。

已经生效的东西会保留：入口列在第一句台词之前做的数值调整、角色出场、界面挂载、背景音，都还在。

所以如果你的入口列在第一句台词之前有重要的初始化，直达时会照常生效；台词之后的那部分则不会跑。

另一个已知限制：进了那一列之后按「重开」，会回到入口列，不是回到你刚才那一列。

## 桌面形态

桌面开发命令同样接受这个参数：

```sh
pnpm tauri dev --story-name inn
```

它走的是同一条通道，章节 id 靠环境变量传给桌面链里的开发服务器，再由它交给页面。

## 脚手架产物也有这条通道

用生成器建出来的工程同样支持：开发命令会先读工程里编译好的故事产物，列出有哪些列，然后照列 id 跳过去。

```sh
npm run dev -- --story-name title_main
```

模板工程里自带两条示例列（`title_main` 与 `look_around`），不用先编译故事就能试。

小程序形态不在此列：它的开发命令由小程序工具链接管，参数形态与这里不同。

## 接到自己的宿主里

通道很短：把列 id 用一个环境变量传给页面，页面读到后直接进那一列。引擎本来就支持「跳到指定列」，不需要改引擎。
