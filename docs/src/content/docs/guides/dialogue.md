对话就是一串 `say`。每条 `say` 建立一次等待点，玩家点击或按键后往下走。

## 一行对话

```text
label start:
  say "夜里十一点，雨还没停。"
  say "街角那家店还亮着灯。"
```

`say` 后面第一个引号串是正文。文本形态下缺正文会在解析期报「say 缺少 text 字符串」并拒绝整个文件；JSON 形态下运行期报 `say-invalid`。两种都不放行空台词。

正文里的 `{` 有特殊含义，见下面的插值和行内标记两节。

## 谁在说话

`speaker=` 或 `by=` 给这一句指定说话人，两者等价：

```text
say "你迟到了。" speaker="阿澈"
say "路上堵。" by="林"
```

说话人会显示在对话框上方。不写就没有说话人，只有正文。

`character` 先注册角色，之后 `say` 的 `speaker` 就能查到它：

```text
character "阿澈" name="阿澈" color="#7aa2f7" textColor="#c0caf5"
say "你迟到了。" speaker="阿澈"
```

`character` 支持 `name` / `color` / `size` / `font` / `textColor` / `screen` 六个字段，只写你要改的。**同名的第二次 `character` 是整条替换，不是合并**——第一次写了 `color`，第二次只写 `name`，颜色就没了。

`character` 的 `key` 是查表用的名字，`say speaker` 用同一个字符串才命中。

## 颜色

三个地方能定说话人颜色，优先级从高到低：

1. `say color="#FFD700"` —— 只影响这一句。
2. `character` 的 `color`。
3. 都没有，就是空串，由你的宿主决定显示成什么。

`say color` 只认十六进制：`#888`、`#FFD700`、`#FFD700CC` 都行，写 `red` 会报 `say-invalid-color`。

```text
say "别动。" speaker="阿澈" color="#f7768e"
```

颜色是**覆盖**语义：这一句写了就写，没写就写空串。所以上一句的红色不会漏到下一句。

## 行内标记

正文里可以夹样式标记，渲染成对应效果：

| 标记 | 效果 |
| --- | --- |
| `{b}` `{/b}` | 加粗 |
| `{i}` `{/i}` | 斜体 |
| `{u}` `{/u}` | 下划线 |
| `{color=#FFD700}` `{/color}` | 染色 |
| `{font=楷体}` `{/font}` | 换字体 |
| `{size=22}` `{/size}` | 换字号 |

```text
say "他说：{b}别动{/b}。然后{color=#f7768e}灯灭了{/color}。"
```

注意 `{color=#FFD700}` 是给**一段文字**染色，`say color=` 是给**说话人**染色。名字像，作用不一样。

标记可以不闭合，渲染时会补齐。写错了也只是看起来怪，不会让工程打不开。

## 变量插值

正文里的 `{变量名}` 会被替换成变量的值：

```text
set "player.gold" 7
say "你有 {player.gold:000} 枚金币。"     →  你有 007 枚金币。
set "code" 255
say "十六进制是 {code:X}。"              →  十六进制是 FF。
```

`0` 是补零位数，`X` 是大写十六进制，`x` 是小写。数字以外的值带格式无效，原样输出。

数组和字典不能直接插进文本，会报 `type-error`，错误信息是「文本插值不支持数组/字典值」。要显示就先把某个元素取出来存进变量。

### 插值和行内标记撞名

`{i}` 既可能是斜体标记，也可能是变量 `i`。规则是：

- `i` 有定义 → 当变量，插值。
- `i` 没定义 → 当标记，斜体。

所以别用 `b` / `i` / `u` / `w` / `p` / `fast` / `color` / `font` / `size` 当变量名。真要用，就写成 `{i}` 之外的路径，比如 `player.i`。

插值失败不会让游戏崩：原文照原样显示，引擎同时抛一个错误给宿主。这是刻意的——一句台词里有个笔误，不该让整个工程打不开。

## 打字机与停顿

对话框默认逐字显示。三个控制符管节奏：

| 写法 | 作用 |
| --- | --- |
| `{p}` 或 `{w}` | 打到这里停一下，等玩家点一次再继续 |
| `{fast}` | 从这里开始不再逐字，直接出 |

```text
say "雨还在下。{p}他把伞递过来。"
```

样式标记是零宽的——`{b}` 不占用打字时间，也不会出现在玩家看到的字符里。打到一半时显示的前缀永远是一个完整的标记，不会露出 `{b` 这样的半截。

玩家点击的三种结果：停在 `{p}` 上就跳过停顿继续打；还没打完就直接打完；已经打完就往下走。这三级是同一个点击入口，你的宿主调一次 `advance()` 就行。

故事级速度用 `text_typewriter` 调：

```text
text_typewriter speed=30
```

`speed` 是每秒多少字符。也可以 `text_typewriter enabled=false` 直接关掉逐字，或者两个一起写。写了 `enabled` 不写 `speed`，速度保持上次的值。

玩家偏好如果存在，优先级高于故事设置——这是宿主层的合成，引擎只写状态。

## 全屏叙事

`nvl` 把接下来的 `say` 累积到全屏文本层，而不是一句一句替换对话框：

```text
nvl
say "第一章"
say "那天之后，事情变得复杂。"
nvl clear
say "第二章"
```

四个子命令：

| 子命令 | 作用 |
| --- | --- |
| 不写 | 进入累积层 |
| `auto` / `enter` | 同不写，进入累积层 |
| `clear` | 清空累积内容，继续累积 |
| `exit` | 清空并退出累积层 |

累积内容随状态走，回溯和读档都会连内容一起恢复。

## 语音

`voice=` 给这一句绑语音，玩家推进过这句就自动停：

```text
say "你迟到了。" speaker="阿澈" voice="Audio/voice/ache_01.mp3"
```

语音走独立的 voice 通道，和 `bgm` / `ambient` / `se` 互不干扰。想手动停用 `stop_voice`。

## 立绘

`character` 只管名字和样式，不管画面。立绘是一个舞台元素，用 `show` 加进元素列：

```text
scene stage:
  show "Images/ache.png" id="ache" x=10% y=0
  say "你迟到了。" speaker="阿澈"
```

`show` 的位置参数是资源路径，写进元素的 `source`。`id=` 给它一个名字，之后 `hide "ache"`、`zindex "ache" value=5`、`animate "ache" ...` 都用这个名字寻址。

元素列（`scene` 开头的列）进入时整体装载，离开时清空。所以立绘写在 `scene` 列里会跟着列一起进退。

`show` 的元素类型是 `image`。想要更细的控制——比如用 `portrait` 类型、加按钮、套容器——直接在 `scene` 列里写元素行，那些是声明式的，不走 op。

立绘和对话层是两个层，各管各的。对话层的 z 用 `say z=` 调，只影响那一句；元素层的 z 用 `zindex` 或元素自己的 `zindex=` 属性。
