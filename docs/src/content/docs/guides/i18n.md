多语言的机制是一条规则：给一段原文，查表拿译文。表放在 `Resources/Lang/`，键是原文，值是译文。

```json
{
  "你好，{player.name}！": "Hello, {player.name}!",
  "接下来去哪里？": "Where to next?"
}
```

键带着 `{player.name}`——插值发生在查表**之后**，所以译文里可以照写占位符，两边共用同一份变量。

端口、语言枚举、加密的机制说明在[多语言与译文](/concepts/i18n/)。这一页按顺序走一遍落地流程。

## 选布局

三种布局，落盘位置不同：

| 布局       | 落盘路径                      | 什么时候选它             |
| ---------- | ----------------------------- | ------------------------ |
| 单文件     | `Lang/{lang}.json`            | 词条不多，一个文件装得下 |
| 主表       | `Lang/{lang}/main.json`       | 想留出加别的文件的位置   |
| 按故事镜像 | `Lang/{lang}/<故事路径>.json` | 故事本来就分目录         |

按故事镜像的路径跟 `Stories/` 对齐，去掉扩展名即可：`Stories/chapter1/tavern.story` 的译文放 `Lang/en/chapter1/tavern.json`。骨架生成按这个规则算路径，你手写时也照它写。

主表和按故事镜像可以混着用：`main.json` 是全局兜底层，最先合并，其余文件按路径顺序覆盖它，同一个键后合并的赢。所以把跨章节复用的句子放 `main.json` 翻一次，各章独有的放章节文件里。

单文件是目录不存在时的降级形态，不能跟另外两种混。`Lang/en/` 目录和 `Lang/en.json` 同时存在时，目录赢——单文件那份不读。

换布局不改键集合：三种布局只是键的摆放位置不同，抽出来的键是同一份。从单文件迁到目录（或反过来），把已有译文按键搬过去即可，不会多出或丢掉词条。命令行体检会核对三种布局生成的键集合是否一致（见下文）。

译文文件里的值必须全是字符串。有一个值不是字符串，**整个文件作废**（跳过的是文件，不是那一行），原文照常显示，看起来很像「没生效」。

## 生成骨架

骨架是把故事里所有可翻译的原文抽出来当键、值先占位的一份译文表。手抄键容易错一个标点就永远查不中，所以用工具生成。编辑器面板的流程如下，命令行等价物见下文的 `lingfan-i18n skeleton`：

1. 在仓库根跑 `pnpm editor`，打开 http://localhost:1425 。
2. 工具栏「打开工程…」选到工程根（含 `Resources/` 的那一层），并授予编辑权限。
3. 右栏切到「本地化」，面板底部「新建语言」：填语言码，选布局，点「生成骨架」。

布局下拉里的三项就是上表：`按主表（Lang/{lang}/main.json）`、`单文件（Lang/{lang}.json）`、`按故事镜像`，默认第一个。语言码得是单段安全文件名——`en`、`zh-CN`、`pt-BR` 都行，`../x` 会被拒：

```text
语言码不合法：../x（须为单段安全文件名）
```

键按故事算：镜像布局下 `Stories/chapter1/tavern.story` 的键写进 `Lang/en/chapter1/tavern.json`；主表和单文件布局把所有故事的键并到一个文件。生成完提示文件数，然后重新枚举工程，新语言立刻出现在面板里：

```text
已生成 en 骨架：3 个文件
```

语言已存在时会先问一句「仍要生成骨架吗？已有译文会被保留（增量模式），但可能覆盖同名文件。」增量模式保留你已经翻好的值，包括**故意留的空串**。所以重复生成是安全的，键有增减时用它补。

骨架的值默认填原文，等于一份翻译工作表：把值改成译文就行。还有一种是空串占位，键照样建、值写 `""`——运行期命中即用，那句话在该语言下直接不显示。编辑器面板走的是默认的原文占位，想用空串占位就自己把值清空。

落盘走编辑器的写回通道，需要能写回的工程打开方式，只读快照打开的工程会提示：

```text
生成骨架需要写回能力。请先「打开工程」并授予编辑权限。
```

## 翻译与保存

点面板里的语言码，或从缺译清单点「去译」，进译文表：左边原文键，右边译文，可以增行、删行、改行。

输入即暂存，**保存是显式动作**——出现脏标记后点保存才写盘。空译文显示成灰色占位而不是空白，因为空白分不清「还没译」和「故意留空」，而这两件事在运行期结果完全不同。

新增行会先问键名：「请输入原文键（须与原文一致；运行期按此键查译文）。」键必须和故事里的字逐字一致，多一个空格就查不中。删行会二次确认，译文表不带备份。

## 看进度

面板顶部是覆盖率：主显示按**字数**加权，悬停能看到按条数的百分比和原文总字数。

条数比会高估完成度——没译的往往是短词，几十条里漏两条看着还有 98%，可玩家读到的那句就是原文。加权按原文长度算权重，长句没翻扣得更狠，接近译者的体感。

状态有四种：`无可译内容`、`尚未开始`、`部分已译`、`已全部译出`。旁边显示 `已译/总数`，点「缺译」展开清单，每条后面跟一个「去译」，直接跳到译文表并定位到那一行。

## 跑翻译体检

翻完跑一遍诊断面板，跟译文有关的有几条警告。命令行也能跑同一套对账，还能当 CI 门禁用（见下文的 `lingfan-i18n`）。

漏译：

```text
原文未有任何译文：欢迎回来（所有语言的 overlay 均未命中——运行期回退原文；专有名词等有意保留原文的可忽略）
```

这条只在工程确实有译文键时才提醒。一份 `Lang/` 都没有的工程不报——那种工程本来就该原文直出。

多译：

```text
未使用的译文键：欢迎回来（say / menu / input / notify 四个翻译面均未命中原文——该键运行期不会生效；若这段文字只用于元素文本或宿主界面，本条可忽略）
```

多译的来源通常是改了原文没改译文：故事里那句换成了别的字，旧键就成了永远查不中的孤儿。消息里列的四个命令面是简称：实际参与比对的是五个命令面（`say` 的正文与说话人、`menu`、`input`、`notify`、`character` 的 `screen`），加上元素 `text` 和宿主源码里包了 `t()` 的静态文案键。

工作台底部的「全部语言合计多译 N 条」和诊断面板的「未使用的译文键」是同一份数据。

另外两条跟宿主与文件摆放有关：

- **宿主未标记文案**：宿主源码里有含中文、却没包 `t()` 的字面量。它们不进键集合，永远不会被翻译；诊断给出文件与行列位置，把面向玩家的文案包起来即可。
- **布局冲突**：同一语言下同一个键出现在多个文件里且取值不一。合并是后写胜，冲突意味着某份译文被静默遮蔽——把重复的键清到只剩一处。

## 命令行工具链：lingfan-i18n

编辑器面板适合边看边翻；批量生成、对账和 CI 门禁走命令行。模板工程的开发依赖里已带 `@lingfan-engine/editor`，在工程根直接跑：

```bash
pnpm exec lingfan-i18n <子命令> [工程根] [选项]
```

工程根按三级回落确定：位置参数 > 环境变量 `DSH_I18N_ROOT` > 当前目录。四个子命令：

| 子命令     | 做什么                                   | 写盘吗 |
| ---------- | ---------------------------------------- | ------ |
| `scan`     | 键清单：故事键 + 宿主键 + 动态调用点     | 否     |
| `skeleton` | 生成/更新一种语言的译文骨架              | 是     |
| `report`   | 一种语言的对账报告（缺译、多译、覆盖率） | 否     |
| `check`    | 与 report 同源的对账 + 退出码门禁        | 否     |

故事面只读**编译产物**收键（不扫故事源码），宿主面扫源码。所以跑之前先把故事编译一遍（见 [TS 故事源码](/advanced/ts-story-source/)），键才是新的。

### scan：看看有哪些键

```bash
pnpm exec lingfan-i18n scan
```

```text
故事键 42 条（3 个编译产物）
宿主键 7 条（5 个源文件）
动态调用点 0 处（登记调用首参均为字面量）
```

首参不是字面量的 `t()` 调用收不到键，会单列出来提醒：

```text
动态调用点 1 处（首参非字面量，无法静态收键）：
- src/host/toolbar.ts:18:12 t()
```

含中文却没包 `t()` 的宿主字面量也在这里报（宿主未标记文案）。默认只收含中文的字面量；`--all` 连不含中文的一起收。

### skeleton：生成骨架

```bash
pnpm exec lingfan-i18n skeleton --lang=en --layout=main
```

`--lang` 必填；`--layout` 取 `single` / `main` / `per-story`，缺省 `per-story`。占位策略 `--placeholder=original|empty`，缺省 `original`（原文占位，当翻译工作表用）；`empty` 是空串占位，运行期命中即隐句。

生成是幂等增量的：已有译文原样保留，只补新键；内容与磁盘一致的文件不触碰：

```text
骨架 3 个文件（写入 2，未变 1）
```

`--prune` 顺手删掉无源的孤儿键——这是破坏性操作，默认关闭；开了会逐条列出被删的键。计划之外的孤儿文件只显式诊断，不会实删。

### report 与 check：对账和门禁

```bash
pnpm exec lingfan-i18n report --lang=en
pnpm exec lingfan-i18n check --fail-on=any
```

`report` 要 `--lang`，输出该语言的缺译、孤儿键、未标记文案与覆盖率：

```text
[en] 覆盖率 88%（字数加权 62%，52/60 键）
```

`check` 缺省对**全部语言**逐一对账（`Lang/` 为空或不存在时提示「未发现任何 overlay」），末尾核对三种布局生成的键集合是否一致——布局只改文件组织、不改键集合，这条核对只报告、不阻断：

```text
三布局键集合一致性：通过（只报告，不阻断）
check 通过
```

`--fail-on` 决定什么算失败：`missing`（缺译文，缺省）、`unused`（孤儿键）、`any`（缺译、孤儿、未标记静态文案任一）。失败时打印 `check 失败（fail-on=…）` 并以非零码退出，可直接接进 CI。

退出码约定：**0** 成功；**1** check 失败或读写失败；**2** 参数错误。

### 登记别的翻译函数名：--functions

扫描器默认只认 `t()`。宿主把翻译函数起了别名（比如 `tr`），用 `--functions` 登记，逗号分隔：

```bash
pnpm exec lingfan-i18n scan --functions=t,tr
```

取值按三级回落：命令行 `--functions` > 工程清单 `project.json` 的 `i18n.functions` > 缺省 `["t"]`。清单写法：

```json
{
  "i18n": {
    "functions": ["t", "tr"]
  }
}
```

清单段必须是对象、`functions` 必须是字符串数组，空清单或空函数名会被拒——宁可报错，不静默漏扫。

所有子命令都支持 `--json`，输出机器可读的结果，方便脚本二次处理。

## 哪些文字会进表

写故事时按下表判断哪些字要翻：

| 位置                      | 进表吗 |
| ------------------------- | ------ |
| `say` 的正文              | 是     |
| `say` 的说话人名          | 是     |
| `menu` 的提示与选项文案   | 是     |
| `input` 的提示与选项文案  | 是     |
| `notify` 的文本           | 是     |
| `character` 的 `screen`   | 是     |
| 元素 `text`               | 是     |
| 宿主包了 `t()` 的静态文案 | 是     |
| `menu` 选项的目标列       | 否     |
| 变量值、表达式结果        | 否     |
| `project.json` 的 `name`  | 否     |

`character` 的 `screen` 是角色的对话框模板注册名，值通常是 `bubble` 这类英文标识符，一般不用翻；但它是字符串字段，所以确实在表里。角色的显示名是 `name`，那个走 `say` 的说话人名。

目标列不进表——它是列 id。`input` 候选的 `value` 也不进——那是要写进变量的原样值。变量值和表达式结果同样不进——那些是数据，不是文案。玩家输入的名字也不进。

## 切换语言

```ts
await engine.setLanguage("en");
```

启动之前也能调，这是给标题画面的语言选择用的。

切换成功后**当前画面立即重译**：正在显示的那句 `say`、菜单与输入的提示和选项、屏幕上的元素文字、NVL 里已滚出的行，都换成新语言。状态里存的是原文，译文在读的那一刻按当前译文表派生，所以不用等下一句、也不用重进场景。

快照与存档同样存原文。读档后显示什么语言，取决于读档时的语言设置；回溯到任一检查点，画面与历史面板也按当前语言派生。旧版本存档里存的是译文，读入时引擎会把疑似译文的字段跳过查表，避免二次误译——存档格式没变，不需要迁移。

失败时**保持原语言**，译文表也不动，同时抛 `i18n-overlay-failed`：

```text
载入 en 译文 overlay 失败（保持原语言）：Failed to fetch
```

传空串回到原文直出——`project.json` 的 `lang` 只是工程元数据，引擎不会据此自动载入它的译文（见[多语言与译文](/concepts/i18n/)）。

## 语言选择器

语言列表由宿主给。模板宿主不做运行期扫描：清单是构建期扫 `Resources/Lang/` 得出的（`virtual:lang-list` 虚拟模块，经 `src/langs/` 出口），运行期照单取件，加语言目录不必改名单。门面的 `availableLangs` 恒含默认语言，接了供给端口时异步补齐；列表取失败就保持缺省，不报错。

模板已经把这条供给接好了：浏览器与桌面壳形态都走 Web fetch——`Lang/` 是静态资源，桌面壳的 WebView 同样取到；小程序形态走可注入的 HTTP 客户端。拿模板跑起来，`Lang/` 直接参与，页面上就有语言选择器。

自己接选择器时注意两个细节：

- **默认语言选项的 `value` 必须是空串**。引擎把空串当「默认语言、原文直出」；填成 `zh-CN` 这类语言码会被当成一次真正的切换，没有对应译文表就按失败处理。选项的显示标签用语言码本身即可——语言名是数据，不翻译。
- 切换成功后要重画宿主自己的静态文案（工具条按钮、存档标签这类包了 `t()` 的字面量），并重挂载缓存了文案的面板（偏好、历史）。模板的接法在 `src/host/i18n.ts`，可直接参考。

参考宿主在列表长度大于 1 时才显示选择器——只有一种语言时显示它没有意义。端口契约与门面 API 见[多语言与译文](/concepts/i18n/)。

## 加密译文

`Lang/en/main.json.enc` 和 `Lang/en/main.json` 一起被收集，收集时解密，然后按同样的规则合并。密文要能解，得在 `project.json` 里声明 `resourceEncryption`；出现密文却没声明，整次载入按失败处理，保持原语言。

## 查表的几条规则

- 命中就用译文，**空串译文也算命中**——写 `""` 是「显示为空」，不是「用原文」。
- 没命中就用原文。
- 原文本身是空串，返回空串，不查表。

## 一个完整例子

按故事镜像 + 主表兜底，工程长这样：

```text
Resources/
  project.json
  Stories/
    chapter1/tavern.story
  Lang/en/
    main.json                跨章节复用的句子
    chapter1/tavern.json     镜像 Stories/chapter1/tavern.story
```

`main.json`：

```json
{
  "要继续吗？": "Do you want to continue?"
}
```

`chapter1/tavern.json`：

```json
{
  "先问一句：你叫什么名字？": "First, what should I call you?",
  "你好，{player.name}！": "Hello, {player.name}!",
  "接下来去哪里？": "Where to next?",
  "去码头": "Head to the docks",
  "回家": "Go home"
}
```

故事 `Stories/chapter1/tavern.story`：

```text
label start:
  input "先问一句：你叫什么名字？" store="player.name"
  say "你好，{player.name}！"
  menu "接下来去哪里？"
    "去码头" -> dock
    "回家" -> home
```

`input` 的提示和 `say` 的正文都查表。玩家输入的名字不进表——它是数据。`menu` 的选项文案查表，目标列 `dock` / `home` 不查。

`chapter1/tavern.json` 那几个键可以让骨架生成起头。`main.json` 那份得手写：镜像布局按故事分文件，不会替你合并不同故事里的同一句原文，跨章节复用的句子放这里才翻一次。
