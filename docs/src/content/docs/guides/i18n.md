多语言的机制是一条规则：给一段原文，查表拿译文。表放在 `Resources/Lang/`，键是原文，值是译文。

```json
{
  "你好，{player.name}！": "Hello, {player.name}!",
  "接下来去哪里？": "Where to next?"
}
```

键带着 `{player.name}`——插值发生在查表**之后**，所以译文里可以照写占位符，两边共用同一份变量。

端口、语言枚举、加密的机制说明在[多语言与译文](/concepts/i18n/)。这一页按顺序走一遍落地流程。

## 选布局

三种布局，落盘位置不同：

| 布局 | 落盘路径 | 什么时候选它 |
| --- | --- | --- |
| 单文件 | `Lang/{lang}.json` | 词条不多，一个文件装得下 |
| 主表 | `Lang/{lang}/main.json` | 想留出加别的文件的位置 |
| 按故事镜像 | `Lang/{lang}/<故事路径>.json` | 故事本来就分目录 |

按故事镜像的路径跟 `Stories/` 对齐，去掉扩展名即可：`Stories/chapter1/tavern.story` 的译文放 `Lang/en/chapter1/tavern.json`。骨架生成按这个规则算路径，你手写时也照它写。

主表和按故事镜像可以混着用：`main.json` 是全局兜底层，最先合并，其余文件按路径顺序覆盖它，同一个键后合并的赢。所以把跨章节复用的句子放 `main.json` 翻一次，各章独有的放章节文件里。

单文件是目录不存在时的降级形态，不能跟另外两种混。`Lang/en/` 目录和 `Lang/en.json` 同时存在时，目录赢——单文件那份不读。

译文文件里的值必须全是字符串。有一个值不是字符串，**整个文件作废**（跳过的是文件，不是那一行），原文照常显示，看起来很像「没生效」。

## 生成骨架

骨架是把故事里所有可翻译的原文抽出来当键、值先占位的一份译文表。手抄键容易错一个标点就永远查不中，所以用编辑器生成：

1. 在仓库根跑 `pnpm editor`，打开 http://localhost:1425 。
2. 工具栏「打开工程…」选到工程根（含 `Resources/` 的那一层），并授予编辑权限。
3. 右栏切到「本地化」，面板底部「新建语言」：填语言码，选布局，点「生成骨架」。

布局下拉里的三项就是上表：`按主表（Lang/{lang}/main.json）`、`单文件（Lang/{lang}.json）`、`按故事镜像`，默认第一个。语言码得是单段安全文件名——`en`、`zh-CN`、`pt-BR` 都行，`../x` 会被拒：

```text
语言码不合法：../x（须为单段安全文件名）
```

键按故事算：镜像布局下 `Stories/chapter1/tavern.story` 的键写进 `Lang/en/chapter1/tavern.json`；主表和单文件布局把所有故事的键并到一个文件。生成完提示文件数，然后重新枚举工程，新语言立刻出现在面板里：

```text
已生成 en 骨架：3 个文件
```

语言已存在时会先问一句「仍要生成骨架吗？已有译文会被保留（增量模式），但可能覆盖同名文件。」增量模式保留你已经翻好的值，包括**故意留的空串**。所以重复生成是安全的，键有增减时用它补。

骨架的值默认填原文，等于一份翻译工作表：把值改成译文就行。还有一种是空串占位，键照样建、值写 `""`——运行期命中即用，那句话在该语言下直接不显示。编辑器面板走的是默认的原文占位，想用空串占位就自己把值清空。

落盘走编辑器的写回通道，需要能写回的工程打开方式，只读快照打开的工程会提示：

```text
生成骨架需要写回能力。请先「打开工程」并授予编辑权限。
```

## 翻译与保存

点面板里的语言码，或从缺译清单点「去译」，进译文表：左边原文键，右边译文，可以增行、删行、改行。

输入即暂存，**保存是显式动作**——出现脏标记后点保存才写盘。空译文显示成灰色占位而不是空白，因为空白分不清「还没译」和「故意留空」，而这两件事在运行期结果完全不同。

新增行会先问键名：「请输入原文键（须与原文一致；运行期按此键查译文）。」键必须和故事里的字逐字一致，多一个空格就查不中。删行会二次确认，译文表不带备份。

## 看进度

面板顶部是覆盖率：主显示按**字数**加权，悬停能看到按条数的百分比和原文总字数。

条数比会高估完成度——没译的往往是短词，几十条里漏两条看着还有 98%，可玩家读到的那句就是原文。加权按原文长度算权重，长句没翻扣得更狠，接近译者的体感。

状态有四种：`无可译内容`、`尚未开始`、`部分已译`、`已全部译出`。旁边显示 `已译/总数`，点「缺译」展开清单，每条后面跟一个「去译」，直接跳到译文表并定位到那一行。

## 跑翻译体检

翻完跑一遍诊断面板，跟译文有关的是两条警告。

漏译：

```text
原文未有任何译文：欢迎回来（所有语言的 overlay 均未命中——运行期回退原文；专有名词等有意保留原文的可忽略）
```

这条只在工程确实有译文键时才提醒。一份 `Lang/` 都没有的工程不报——那种工程本来就该原文直出。

多译：

```text
未使用的译文键：欢迎回来（say / menu / input / notify 四个翻译面均未命中原文——该键运行期不会生效；若这段文字只用于元素文本或宿主界面，本条可忽略）
```

多译的来源通常是改了原文没改译文：故事里那句换成了别的字，旧键就成了永远查不中的孤儿。消息里写「四个翻译面」是旧文案，比对时实际用了五个（多一个 `character` 的 `screen`），外加元素 `text`。

工作台底部的「全部语言合计多译 N 条」和诊断面板的「未使用的译文键」是同一份数据。

## 哪些文字会进表

写故事时按下表判断哪些字要翻：

| 位置 | 进表吗 |
| --- | --- |
| `say` 的正文 | 是 |
| `say` 的说话人名 | 是 |
| `menu` 的提示与选项文案 | 是 |
| `input` 的提示 | 是 |
| `notify` 的文本 | 是 |
| `character` 的 `screen` | 是 |
| 元素 `text` | 是 |
| `menu` 选项的目标列 | 否 |
| 变量值、表达式结果 | 否 |
| `project.json` 的 `name` | 否 |

`character` 的 `screen` 是角色的对话框模板注册名，值通常是 `bubble` 这类英文标识符，一般不用翻；但它是字符串字段，所以确实在表里。角色的显示名是 `name`，那个走 `say` 的说话人名。

目标列不进表——它是列 id。变量值和表达式结果也不进——那些是数据，不是文案。玩家输入的名字同样不进。

## 切换语言

```ts
await engine.setLanguage("en");
```

启动之前也能调，这是给标题画面的语言选择用的。

切完之后当前这一句不会重翻，下一次取译文时才生效：下一句 `say`、下一个 `menu` 的提示和选项、下一次进 `scene` 列装载的元素文本。`say` 每次执行都重新查表，所以往下走一句就能看到新语言。

元素文本不一样：它在装载时翻译，翻好的值进状态容器，跟着快照、存档、回溯走。这是有意的——回退到英文进度时，画面不该突然变回中文。

失败时**保持原语言**，译文表也不动，同时抛 `i18n-overlay-failed`：

```text
载入 en 译文 overlay 失败（保持原语言）：Failed to fetch
```

传空串回到原文直出——`project.json` 的 `lang` 只是工程元数据，引擎不会据此自动载入它的译文（见[多语言与译文](/concepts/i18n/)）。

## 语言选择器

语言列表由宿主给：扫 `Lang/` 的直接子项，目录名或去掉 `.json` / `.json.enc` 后缀的文件名就是一个语言码。列表里恒含 `zh-CN`，`Lang/` 不存在或扫不动也只返回它，不报错。

选择器在列表长度大于 1 时才出现——只有一种语言时显示它没有意义。参考宿主就是这么做的。

译文由宿主提供，引擎通过 `i18nPort` 要数据。**模板自带的宿主没有接这个端口**，所以拿模板跑起来时 `Lang/` 完全不参与、原文直接显示。这不是译文写错了，是宿主还没接。参考宿主的桌面壳形态已经接上了原生供给：Tauri 侧扫 `Lang/`、按需读取、密文顺手解密，再交引擎合并。想自己接，接口形状见[多语言与译文](/concepts/i18n/)。

## 加密译文

`Lang/en/main.json.enc` 和 `Lang/en/main.json` 一起被收集，收集时解密，然后按同样的规则合并。密文要能解，得在 `project.json` 里声明 `resourceEncryption`；出现密文却没声明，整次载入按失败处理，保持原语言。

## 查表的几条规则

- 命中就用译文，**空串译文也算命中**——写 `""` 是「显示为空」，不是「用原文」。
- 没命中就用原文。
- 原文本身是空串，返回空串，不查表。

## 一个完整例子

按故事镜像 + 主表兜底，工程长这样：

```text
Resources/
  project.json
  Stories/
    chapter1/tavern.story
  Lang/en/
    main.json                跨章节复用的句子
    chapter1/tavern.json     镜像 Stories/chapter1/tavern.story
```

`main.json`：

```json
{
  "要继续吗？": "Do you want to continue?"
}
```

`chapter1/tavern.json`：

```json
{
  "先问一句：你叫什么名字？": "First, what should I call you?",
  "你好，{player.name}！": "Hello, {player.name}!",
  "接下来去哪里？": "Where to next?",
  "去码头": "Head to the docks",
  "回家": "Go home"
}
```

故事 `Stories/chapter1/tavern.story`：

```text
label start:
  input "先问一句：你叫什么名字？" store="player.name"
  say "你好，{player.name}！"
  menu "接下来去哪里？"
    "去码头" -> dock
    "回家" -> home
```

`input` 的提示和 `say` 的正文都查表。玩家输入的名字不进表——它是数据。`menu` 的选项文案查表，目标列 `dock` / `home` 不查。

`chapter1/tavern.json` 那几个键可以让骨架生成起头。`main.json` 那份得手写：镜像布局按故事分文件，不会替你合并不同故事里的同一句原文，跨章节复用的句子放这里才翻一次。
