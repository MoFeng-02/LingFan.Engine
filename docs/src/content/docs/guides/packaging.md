开发时工程是明文：`Resources/` 下是能直接打开的文件，`project.json` 里 `resourceEncryption` 是 `false` 或没有这个字段。玩家手上的包不能这样——资源得是密文，前端产物也得是密文，只剩一个入口 `index.html` 明文留给壳加载。

这一步不是一条命令，是三步。下面按顺序说，每步都要看输出。

## 一、加密构建前端壳

```bash
LFEN_ENCRYPTED_BUILD=1 pnpm tauri build
```

这个环境变量是唯一的开关，不加就是普通构建。它在 `pnpm build` 之后跑的收尾脚本里生效，做四件事：

- 把 `dist/index.html` 里的 `./assets/…` 引用改写成走壳内协议的地址（`{协议基座}/v2/dist%2Fassets%2F…`）。协议基座按宿主平台推断：`darwin` 与 `linux` 用 `lfstream://localhost`，其余用 `http://lfstream.localhost`；也可以用 `LFEN_PROTOCOL_BASE` 显式指定（iOS 构建就需要）。
- 把 `dist/assets` 整个移到 `dist-enc/assets/`，**保留 `assets/` 这一层**。包里这些产物的逻辑路径前缀是 `dist/assets/…`，和刚改写出来的 URL 必须逐字对应；少一层，运行时就是 404。
- 清掉 `dist` 里除 `index.html` 与 `splashscreen.html` 之外的一切。原因是 vite 的 `publicDir` 指向 `Resources`，构建时会把明文资源整体镜像进 `dist`——留在里面就被嵌进壳了，等于没加密。
- 最后扫一遍 `dist`，只要还残留 `.js` / `.mjs` / `.css` 就直接失败退出，不产出一次「看起来成功」的加密构建。

构建完成后 `dist` 里只有两个 html，`dist-enc/` 里是待加密的产物。`dist-enc` 不是给壳用的，是下一步的输入。

## 二、用 lfenpack 收资源与产物

先把工具编出来（它只在打包机上用，不随玩家包分发）：

```bash
cd apps/playground/src-tauri
cargo build --bin lfenpack --release
```

然后对工程资源根跑一次：

```bash
lfenpack <工程资源根> <输出目录> --dist apps/playground/dist-enc --strict
```

第一个参数是含 `project.json` 的目录，第二个是输出根，不存在就新建；已存在且非空时得加 `--force` 才覆盖（它会先把输出目录整个删掉，所以路径不能与输入相同或互相嵌套，这一点有前置校验）。

`--dist` 把前端产物一起收进包，按 `dist/` 作为逻辑路径前缀。html 不在收录白名单里——入口 html 是要明文嵌进壳的，它出现在 `--dist` 输入里说明上游哪一步错了，会落进报告的「未入包」而不是被悄悄加密。

### 什么进包、什么不进

| 类别             | 处理                                                 |
| ---------------- | ---------------------------------------------------- |
| 故事、译文、清单 | 加密                                                 |
| 图片音频视频     | 加密                                                 |
| 字体             | 加密                                                 |
| `js` / `css`     | 加密（走 v2 存储，运行时按需解密）                   |
| `project.json`   | **明文**，工程元数据要能被读                         |
| `Saves/`         | 排除，运行期生成的东西不进包                         |
| 白名单外的文件   | 未入包，报告里逐条给原因，**不会被静默当明文带进去** |

### 输出

- 每个内容文件一个密文，文件名是原逻辑路径加 `.enc`。
- 一个密钥种子文件，随包分发，首次运行时由平台层导入并立刻用自己的密钥封装起来。
- 清单照原样落地，但 `resourceEncryption` 改成 `true`；收了前端产物时还会多一段 `frontend.assets` 映射。

跑完会打印四类清单：**已加密** / **明文（有因）** / **排除** / **未入包**。前两类里的「明文（有因）」只有 `project.json` 与密钥种子两个——它们是设计上必须明文的那两个，不是漏掉。

`--strict` 的语义是：打包照常完成，但只要报告里出现任何「未入包」或额外的明文例外，就以非零码退出。适合放进自动化流程——例外面必须有人显式知情，不能靠翻日志才发现「有几个文件没进包」。

## 三、把整包放到壳的资源目录

lfenpack 的输出目录整个放进应用的 `resource_dir()/Resources/`。正式分发形态到这里就没有环境变量了：壳启动时找到资源根，读明文清单，看到 `resourceEncryption: true` 就装配加密供给，页面经壳内协议按需取字节。

自检口径三条：页面完整渲染、控制台零错误、在可执行文件与包内搜不到明文的业务 `js` / `css`。

## 现状与限制

说清楚现在缺什么，省得试了半天才发现：

- **没有一条命令把三步串起来。** 加密构建、打包、放资源目录是三次手工动作。构建流程里只挂了「构建 + 收尾」，没有打包那一步。
- **默认构建不加密。** 不加那个环境变量，`pnpm tauri build` 出来的就是明文包，与加密包长得一样但是能直接看源码。
- **加密供给只有桌面壳形态有。** 浏览器形态不做加密供给，编辑器也只开明文工程——把密文目录丢给编辑器，它会直接说打不开。
- **打包机需要 Rust 工具链。** `lfenpack` 是单独的二进制，不是随包分发的运行时组件。
