## v0.2.0

2026-10-26 · [完整说明与提交清单](https://github.com/MoFeng-02/LingFan.Engine/releases/tag/v0.2.0)

### 新增

- **故事源形态**：生成器多问一件事——故事写 `.story` 文件，还是写 TypeScript。选后者得到 `src/Stories.src/`、`stories:build` / `stories:watch` / `stories-typecheck` 三条脚本、独立的 `tsconfig.stories.json`，以及一份开箱可跑的产物，装完直接 `pnpm dev`。详见[TS 创作模式](/advanced/ts-story-source/)。
- **叠加层可删除骨架文件**：层根的 `package.patch.json` 支持 `create.remove`，列出该层要删掉的路径（文件或目录前缀）。合并时先删后写。小程序壳因此能真的删掉骨架的浏览器宿主与页面样式表，而不是靠 `tsconfig` 排除假装它们不存在。
- **输入候选快捷值**：`input` 新增可选 `options`，形态是 `{ text, value }[]`。`text` 是候选按钮上的文字，进翻译表；`value` 是点中后原样写进 `store` 的值，**不进**翻译表——否则多语言下故事逻辑读到的变量会跟着语言漂移。文本格式、TypeScript 词汇层（`inputCandidate`）、运行时状态、状态读口（`StateReader.inputCandidates()`）与选择层界面已全链接通。详见[菜单、输入与通知](/guides/menu-input/)。
- **iOS 屏幕方向**：改为纯 Rust 直调 UIKit，仓库内不再有 Swift。运行期给承载页面的视图控制器换一个动态子类，覆写方向相关的两个选择器；持续锁定靠每次询问都回报当前允许集合。
- **壳内明文资源**：自定义协议新增 `raw/{路径}` 段，按逻辑路径直接供给音视频、图片、字体与文本。壳形态下页面从打包产物加载，而资源落在另一个目录，页面源根相对路径取不到字节——现在由 `resource_url(path)` 命令给出唯一地址，前端不拼路径。
- **一条命令发版**：`pnpm release --bump patch|minor|major` 改八份清单、跑门禁、提交、打注记标签并推远端；标签推上去之后由工作流完成打包与发布。详见[发布新版本](/guides/release/)。

### 优化

- **壳内前端加载**：宿主桥改由组合根注入，不再依赖变量说明符的动态 import。此前壳内页面会整体加载失败、只剩白屏。
- **预发布版本**：`0.2.0-rc.1` 这类写法可直接用，发布时按后缀首段取 dist-tag（`rc` / `alpha` / `beta`），按 `@rc` 安装即可。

### 修复

- **iOS 目标编译**：方向下发调用点与平台实现的返回值对齐，iOS 目标恢复可编译。
- **媒体错误文案**：点名具体是哪个资源取不到，而不是笼统的加载失败。
- **发版脚本**：标签触发的流水线在门禁阶段不再失败——检出标签时 HEAD 是分离头，干跑不该被「必须在 main 上」拦下。

## v0.1.4

2026-10-23 · [完整说明与提交清单](https://github.com/MoFeng-02/LingFan.Engine/releases/tag/v0.1.4)

### 新增

- **工程生成器**：`@lingfan-engine/create`，`npm create @lingfan-engine my-story` 从模板骨架生成工程，替代「复制目录 + 手工替换占位符」。详见[从模板创建工程](/from-template/)。
- **框架叠加层**：Vue 3 与 React 两层。引擎与适配器不认识任何框架，换框架只换页面结构与入口。
- **壳层**：小程序（UniApp）与桌面（Tauri 2）两层。骨架同时开放端口覆盖口，宿主由此接管渲染与平台能力。
- **层声明**：模板用 `template-meta.json` 声明可选层，新增一层只需建同名目录并加一个条目，生成器本身不用改。

### 修复

- **桌面壳**：补齐应用图标与槽位名校验，图标文件不再被当文本改写。

## v0.1.3

2026-10-22 · [完整说明与提交清单](https://github.com/MoFeng-02/LingFan.Engine/releases/tag/v0.1.3)

### 新增

- **发布说明**：正文采纳提交信息里「新增 / 优化 / 修复 / 其他变更」的分节，并附与本版本前一个标签之间的完整变更链接。写成分节的提交才进说明，写成一行的只留那一行。

### 优化

- **发版可重跑**：已经上架的版本自动跳过，中途失败后重跑不会重复发布。

### 修复

- **只在标签上发布**：推包与建 Release 都只在标签触发时执行，手工触发不再能推包。
