## v0.3.6

2026-11-08 · [完整说明与提交清单](https://github.com/MoFeng-02/LingFan.Engine/releases/tag/v0.3.6)

### 修复

- **生成工程类型检查把故事源误当组件**：Vue、React、小程序三种形态生成的工程，根 `tsconfig.json` 的检查面覆盖整个 `src/**`，而这份配置由组件编译器承担（Vue 认 `.vue`、React 认 `.tsx`）。于是故事源里 `import` 组件、把组件句柄传给 `mount()` 时，组件被解析成真实组件类型，盖过引擎声明的句柄通配，判成型不匹配——按文档写 UI 挂载的工程一跑 `typecheck` 就报错。现在三种形态的工程配置都把 `src/Stories.src/**` 排除在组件检查面之外，故事源由自己的 `tsconfig.stories.json` 用纯 `tsc` 检查，`stories-typecheck` 照常覆盖它；宿主页面仍在组件检查面内，改动宿主写错类型照样报错。

### 其他变更

- **模板版本**：`1.12.0` → `1.13.0`。模板内容有变（三种形态的工程 `tsconfig.json`），因此抬版本号；引擎版本线不受影响。

## v0.3.5

2026-11-08 · [完整说明与提交清单](https://github.com/MoFeng-02/LingFan.Engine/releases/tag/v0.3.5)

### 新增

- **工程清单描述字段**：`Resources/project.json` 可写可选的 `description`，是给玩家看的一句话。它不参与寻址，也不影响标题解析，引擎只校验类型；空字符串合法，不写这个键也照常加载。生成器问到的描述会同时写进 `package.json` 与工程清单。
- **生成器改为问答式创建**：命令只带工程名，其余按顺序问——工程名、描述、形态多选。形态一次可选多项，哪些层能叠加由模板的互斥声明决定，选到互斥组合会当场说明并重问；描述可留空，填了写进上面两处清单。标准输入不是终端且仍有待问的项时明确失败，不再静默挂起。`--template` 保留给脚本用法，不参与互斥校验。
- **手写故事示例改为纯加法**：叠加层不再摘掉骨架的 TS 创作链，只额外放一份手写示例 `Resources/Stories/manual/manual_intro.story`。示例列 id 落在 `manual_` 命名空间里，与骨架自带的列不撞名。形态问答随之收窄成页面结构与壳两项，`--sources story` 仍可指定故事源，但不占选项位。

### 优化

- **发布说明生成**：正文按段落成条，`验证：`、`测试：` 这类过程记录整段丢弃，不再混进发布说明；`功能` 归入「新增」类型。

### 修复

- **故事产物清理**：此前 `Resources/Stories` 下不在本轮产物集合里的文件一律删除，会连手写 `.story` 与手写 JSON 列一起删掉。改为读上一轮产物账（工程根 `.lingfan/stories-build.json`），只删自己写过、这一轮不再产出的文件；账缺失时一律不删。手写文件从此不在清理范围内。

### 其他变更

- **文档**：生成器用法改为三段问答，脚本用法收进独立小节；清单参考补 `description` 字段说明；模板骨架说明同步；形态表由五项收成四项（Vue 3、React、桌面 Tauri 2、小程序 UniApp），并补上三种创作形态共存的说明——TS 源、手写 `.story`、手写 `.json` 落在同一棵 `Resources/Stories/` 树上，构建期一起扫描，可以混装。「改一句对话」原先让读者打开骨架里并不存在的 `.story` 文件，改为读 `src/Stories.src/title/title_main.ts`，并说明要跑 `pnpm stories:build`、直接改 `.json` 会被下一次构建覆盖；资源布局示例换成骨架真实文件；模板版本提到 1.12.0。

## v0.3.4

2026-11-07 · [完整说明与提交清单](https://github.com/MoFeng-02/LingFan.Engine/releases/tag/v0.3.4)

### 新增

- **生成器支持 `--template`，故事源不再提问**：故事源只认参数——`--sources story`，或 `--template <框架[-壳[-故事源]]>` 的第三段，缺省 `ts`。`--template` 一次指定形态，逐项参数仍优先。目标目录非空时交互问保留、清空还是取消；`--overwrite` 是非交互清空，`--yes` 遇非空目录直接报错退出，不替人做覆盖决定。依赖缺省不安装，要装给 `--install`，旧 `--no-install` 仍认。

### 修复

- **依赖的钉法**：骨架记录的 `typescript` 钉法（`~6.0.3`，`vue-tsc` 在 TS 7 上会崩）被 registry 解析覆盖成 `^7.0.2`——钉法只从叠加层读，而原生加浏览器这组没有叠加层目录。骨架补一份 `package.patch.json` 声明自己的钉法，叠加层各钉各的、并集生效。同时修掉「钉住的依赖只剩最后一层」：壳层排在框架层之后就整体抹掉前面的钉法。
- **包管理器跟随调用方**：安装命令与后续三步提示不再硬编码 pnpm，按发起方（npm、pnpm、yarn、bun）给对应命令，认不出时退回 npm。
- **桌面壳与框架层叠加**：桌面壳原先自带组合根，只在「原生加浏览器」这组成立；与 Vue 3 或 React 叠加后入口错配——Vue 启动即抛错，React 静默退化成没有桥的 WebView。桥的装配下沉到骨架，三个组合根统一传端口；`@tauri-apps/api` 从壳层下沉到骨架，壳层只留 `@tauri-apps/cli`。

## v0.3.2

2026-11-03 · [完整说明与提交清单](https://github.com/MoFeng-02/LingFan.Engine/releases/tag/v0.3.2)

### 优化

- **宿主插件兼容两代 vite**：模板同时供浏览器壳、桌面壳（vite 8）与小程序壳（插件把 vite 钉在 5.2.8）。`configureServer` 与 `invalidateModule` 写成函数属性时，严格函数类型检查按参数逆变判定失败，消费方类型检查报错；改方法签名后按双变处理，两种 vite 都收得下。
- **宿主插件类型互锁**：补一条类型用例，要求宿主插件同时被 vite 5 与 vite 8 接受。叠加层不进模板工程的类型检查，这个盲区只能等消费方撞上。
- **发布说明认得中文提交类型**：提交类型从 `feat` / `fix` 换成 `新增` / `修复` / `重构` 后，生成器只登记英文，中文标题整条落进「其他变更」。两种写法现在同等对待，`docs` / `chore` / `ci` 与 `文档` / `变更` / `模板` 显式归入「其他变更」。

### 修复

- **React 组合根取节点过早**：`createRoot().render()` 是并发渲染，只保证稍后提交，紧接着读节点句柄读到的是空容器，取节点抛错、页面白屏。改为强制首屏同步落地后再读；`UiHost` 的外层由 `null` 换成 `Fragment`——前者不是合法的调用形态。

### 其他变更

- **模板版本**：抬到 1.8.2，最低引擎版本对齐到 0.3.2（`^0.3.1` 也装得到 0.3.2，但离线生成会退回模板记录的值）。

## v0.3.1

2026-11-03 · [完整说明与提交清单](https://github.com/MoFeng-02/LingFan.Engine/releases/tag/v0.3.1)

### 优化

- **模板类型面互锁**：补一条用例，扫描模板里由 Node 直接执行的两个文件，要求引擎的值导入（`import type` 不算）解析出的运行时落点不是 TS 源码、且真实随包存在。

### 修复

- **构建配置加载**：包以 TS 源码出口，而构建配置由 Node 直接加载。引擎在配置里的运行时落点若是 `.ts`，工程装出来就崩在配置加载，而仓库内因 workspace 链接看不到这一点。`host-plugins` 子路径补一份随包的 `.mjs` 垫片，用自带依赖装载真实实现；exports 改条件导出，类型指回源码。
- **本地插件引用**：构建配置引本地插件时补 `.ts` 扩展名，消掉 vite 的 `configLoader: 'native'` 告警——`native` 是下个大版本的默认加载器，届时无扩展名的相对 import 会直接失败。

### 其他变更

- **模板版本**：抬到 1.8.1。模板内容变了，引擎版本没动。

## v0.3.0

2026-11-03 · [完整说明与提交清单](https://github.com/MoFeng-02/LingFan.Engine/releases/tag/v0.3.0)

### 新增

- **生成器：引擎版本校验**：`minEngineVersion` 此前只是装饰字段，模板按未发布的引擎写，要到用户第一次 `pnpm dev` 才炸、且炸在别处。生成期就拿它跟 registry 的实际版本比对，不达标直接失败并说明差在哪个包、差多少；判定放在写盘之前。
- **模板：存档带缩略图**：WebView 没有跨端截图 API，缩略图是合成卡——阶段底色、工程名、说话人、当前正文、时间戳。尺寸、质量、是否带文本由 `shell.saves.thumbnail` 决定，合成失败降级为无图存档。
- **模板：历史面板与回溯**：新增宿主侧的历史面板，块聚合走引擎（宿主不自写一份，否则面板显示的行与回溯落点会漂移），宿主只画块，点击翻译成回溯到该块尾部的检查点。槽位 `#history` 可选，与偏好面板同口径。
- **模板：存档可起名**：槽位面板顶部加存档名输入框，点槽即存。填了用填的；没填而该槽原有名字就沿用；都没有才自动生成。宿主控制面的存档接口补可选参数透传。
- **模板：启动页自选存档**：启动页第三个按钮展开逐槽列表（缩略图、标题、时间），空槽列出但置灰；槽位数据与「继续」共用同一次刷新。
- **示例：进入即启动页**：示例改为先进启动页选开始或继续，对局中按 Esc 或点挂载面板唤起暂停菜单；新增启动页与暂停页两个宿主页面，组合根不再自动开局。
- **引擎：全局暂停与恢复**：引擎新增 `pause()` / `resume()` / `paused()`；音频端口补 `pause` / `resume`，音频状态从两态变三态，新增暂停与恢复两个命令。暂停态不进快照、不中断外部接管；暂停期间推进与选择显式拒绝，导航与存读档照常。
- **引擎：音频实例维度与音量三级解析**：音频从「一条通道一个声音」扩到「一条通道多个实例」，起停与调音量都能点名实例，新增停音效、按实例播、按实例停、按实例调音量四个命令。音量按实例值、通道值、工程默认值三级解析，工程清单可声明默认音量。音频配置走运行时上下文，不随存档、快照、回溯变化。
- **UI：挂载表与 `mount` 命令**：列产物多一个 `uis` 字段；`mount(handle | name, visible, props)` 是内建命令，props 整份替换，非法字段与不可序列化值 fail-closed；系统键 `__mounts` 双向；骨架新增 `#mounts` 层，UI 盖得住对话层、盖不住转场与错误条。宿主三种接法：给容器与表、只给回调、都不给。生成物按名字导出界面句柄，故事源可直接 import。
- **UI：界面列可挂整屏页面**：标题页、设置页这类需要真正排版的界面，不再用命令一条条堆。页面注册表只管登记与查找，挂载器负责创建、挂上、切走时销毁。模板自带一个标题页示例，不注册页面时一切照旧。
- **引擎：列清单摘要**：只读列清单给出 id、类型、种类三项摘要，不含命令与入口内容；读者接口补当前列 id 与类型两个可选方法。
- **契约：状态键读写方向**：每个状态键标成只读、只写或双向，放在契约层当声明，供展示层判断控件该不该可编辑。
- **UI：元素值回写状态**：控件值变化可写回状态，落点只认音频通道音量或系统键；区分「值在变」与「值已定」，滑动中不写、松手才写；不传回写回调时控件照常可操作，只是值不落地。

### 优化

- **生成器：模板快照增量同步**：Windows 上进程持有目录句柄就删不掉，原先先删快照目录再重建，开发机打包含时必报权限错误。改为按清单同步：先删「上次有这次没有」的，再逐个覆盖。
- **生成器：缺省创作形态改为 TS 故事源**：三种形态是同一份架构的三种写法，TS 编译成同位置的 JSON、能力更强，故缺省换成 ts。构建期依赖只在骨架声明一次，避免两处版本号漏改一处。零改动的形态可以没有叠加层目录。
- **模板：清单扫描收进 `stories-build`**：故事清单是磁盘事实的投影，不该由作者手抄——漏抄要到运行期才以「未知列」现形。扫描实现归构建包，模板只声明资源根在哪；开发时监听目录，增删文件即作废模块并整页刷新。
- **重构：故事源迁入 `src/`**：故事源由 `Stories.src/` 迁到 `src/Stories.src/`，生成物迁到 `src/gen/`，宿主可以当普通模块 import。
- **重构：故事源可 import UI**：UI 说明符走独立通道（`.vue`、`.tsx`、`.html`，`.ts` 仅当落在 `ui/` 下），`ui/` 目录名即 UI 名，注册表自动生成；跨层导入做静态校验。命令行收 `--sources-dir` / `--resources-dir`，读工程 `tsconfig` 的 `paths` 支持任意别名。
- **重构：运行层散文件按职责族归位**：顶层散文件按职责搬进子目录，导出面与包出口路径不变。
- **重构：路径比较器只留一处**：两份逐字节相同的码元序比较器合并到共享模块。
- **重构：模板根目录归位**：骨架根只留唯一入口与类型声明，其余各归其目录；平铺检查的扫描面覆盖模板。
- **引擎：场景类型收两值**：场景类型只留「游戏」与「界面」——菜单、设置、覆盖层、弹窗是同一件事；缺省或非法值一律落游戏，编辑器选项合并为「界面」。

### 修复

- **存档高水位按槽位记**：演示存档端口原先记一个全局计数，槽 2 存档后槽 1 被判「比高水位旧」，读它被拒、槽位列表丢名字与预览。改为每个槽位各记一条高水位；小程序与桌面原生端口同步改，原生端口另把高水位文件挪进独立目录。
- **列级作用域随档**：读档从列级 `let` 声明之前重放，声明不重跑、作用域为空，舞台上 `{a}` 原样显示并伴随变量未定义。存档现在带一份列级层，读档按它重建执行帧；档内历史检查点各自带一份。
- **历史与偏好面板被盖住**：层表的默认层清单漏了这两层，面板的 z-index 停在 auto，被对话层与选项层盖住——面板打开了却看不见。
- **菜单等待期点舞台挂常驻错误条**：舞台点击被无条件映射成推进，引擎只在对话、等待、视频三态放行，其余情况 fail-closed 并把错误写进界面，而错误条没人清。现在先判等待态再推进，打字机没打完仍先补完。
- **示例故事首屏报解析错误**：模板故事里那句「媒体放 `Resources/{Audio,Images,Video}`」被插值器当成表达式，每次播到都报错且错误条常驻。文案改为把三个目录名分开写。
- **框架层的类型声明**：Vue 与 React 层的 `src/vite-env.d.ts` 整文件覆盖骨架同名文件，只声明了字体模块、漏了故事清单模块，生成工程后取故事清单处报找不到模块、类型检查必红（开发时照跑，不易发现）。
- **发行脚本**：推送的输出走管道之外时取回的是空值，收尾处理直接抛错，一次成功的推送被报成失败。

### 其他变更

- **模板：桌面壳依赖与入口**：历史面板块的聚合位于 shell 包，宿主不自写聚合规则；骨架与根 devDependencies 同步声明。
- **仓库检查**：单文件行数纳入机器检查；示例工程目录不进扫描面；宿主层不硬编码列名与工程名；模板与引擎的导出面互锁——引擎加删导出时，模板的具名导入失配会当场红，否则要等生成工程做类型检查才发现。
- **文档站点**：本页上线；补「打包与加密发布」指南；页面一篇按引擎真实边界重写；挂载 UI 与启动界面两篇改写；存档作用域补文档；站点配色收回令牌表；脚手架文档的版本口径与缺省创作形态与实现对齐。

## v0.2.0

2026-10-26 · [完整说明与提交清单](https://github.com/MoFeng-02/LingFan.Engine/releases/tag/v0.2.0)

### 新增

- **故事源形态**：生成器多问一件事——故事写 `.story` 文件，还是写 TypeScript。选后者得到 `src/Stories.src/`、`stories:build` / `stories:watch` / `stories-typecheck` 三条脚本、独立的 `tsconfig.stories.json`，以及一份开箱可跑的产物，装完直接 `pnpm dev`。详见[TS 创作模式](/advanced/ts-story-source/)。
- **叠加层可删除骨架文件**：层根的 `package.patch.json` 支持 `create.remove`，列出该层要删掉的路径（文件或目录前缀）。合并时先删后写。小程序壳因此能真的删掉骨架的浏览器宿主与页面样式表，而不是靠 `tsconfig` 排除假装它们不存在。
- **输入候选快捷值**：`input` 新增可选 `options`，形态是 `{ text, value }[]`。`text` 是候选按钮上的文字，进翻译表；`value` 是点中后原样写进 `store` 的值，**不进**翻译表——否则多语言下故事逻辑读到的变量会跟着语言漂移。文本格式、TypeScript 词汇层（`inputCandidate`）、运行时状态、状态读口（`StateReader.inputCandidates()`）与选择层界面已全链接通。详见[菜单、输入与通知](/guides/menu-input/)。
- **iOS 屏幕方向**：改为纯 Rust 直调 UIKit，仓库内不再有 Swift。运行期给承载页面的视图控制器换一个动态子类，覆写方向相关的两个选择器；持续锁定靠每次询问都回报当前允许集合。
- **壳内明文资源**：自定义协议新增 `raw/{路径}` 段，按逻辑路径直接供给音视频、图片、字体与文本。壳形态下页面从打包产物加载，而资源落在另一个目录，页面源根相对路径取不到字节——现在由 `resource_url(path)` 命令给出唯一地址，前端不拼路径。
- **一条命令发版**：`pnpm release --bump patch|minor|major` 改八份清单、跑门禁、提交、打注记标签并推远端；标签推上去之后由工作流完成打包与发布。详见[发布新版本](/guides/release/)。

### 优化

- **壳内前端加载**：宿主桥改由组合根注入，不再依赖变量说明符的动态 import。此前壳内页面会整体加载失败、只剩白屏。
- **预发布版本**：`0.2.0-rc.1` 这类写法可直接用，发布时按后缀首段取 dist-tag（`rc` / `alpha` / `beta`），按 `@rc` 安装即可。

### 修复

- **iOS 目标编译**：方向下发调用点与平台实现的返回值对齐，iOS 目标恢复可编译。
- **媒体错误文案**：点名具体是哪个资源取不到，而不是笼统的加载失败。
- **发版脚本**：标签触发的流水线在门禁阶段不再失败——检出标签时 HEAD 是分离头，干跑不该被「必须在 main 上」拦下。

## v0.1.4

2026-10-23 · [完整说明与提交清单](https://github.com/MoFeng-02/LingFan.Engine/releases/tag/v0.1.4)

### 新增

- **工程生成器**：`@lingfan-engine/create`，`npm create @lingfan-engine my-story` 从模板骨架生成工程，替代「复制目录 + 手工替换占位符」。详见[从模板创建工程](/from-template/)。
- **框架叠加层**：Vue 3 与 React 两层。引擎与适配器不认识任何框架，换框架只换页面结构与入口。
- **壳层**：小程序（UniApp）与桌面（Tauri 2）两层。骨架同时开放端口覆盖口，宿主由此接管渲染与平台能力。
- **层声明**：模板用 `template-meta.json` 声明可选层，新增一层只需建同名目录并加一个条目，生成器本身不用改。

### 修复

- **桌面壳**：补齐应用图标与槽位名校验，图标文件不再被当文本改写。
