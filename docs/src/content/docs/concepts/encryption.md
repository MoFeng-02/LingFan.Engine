加密不是引擎里的一个开关。引擎只声明它需要什么，组合根决定装哪个实现，密钥和加解密留在平台层。资源、译文、存档三个面各自在这一层的什么位置完成，下面分开说。

## 三层分工

同一个「资源要加密」的需求，落到三层里各是一件事：

| 层 | 它做的事 | 它不知道的事 |
| --- | --- | --- |
| 引擎 | 声明契约。资源要一个能用的地址，译文要一批条目，存档要一个能读写的槽位端口。 | 资源是明文还是密文、密钥在哪、有几个。 |
| 组合根 | 读 `project.json`，看 `resourceEncryption` 和宿主形态，决定装配哪个实现。 | 不持有密钥材料，不做加解密。 |
| 平台层 | 持密钥，解密，把结果落成平台能直接用的东西（地址、字节、槽位文件）。 | 故事讲到哪一列、什么是等待点。 |

换宿主形态只动组合根那两行。引擎侧的等待点、检查点、重放跟加密无关，一个字不用改。

## 资源端口只要一个地址

故事里写 `bgm "Audio/main.mp3"`，这行字在明文工程和加密工程里一模一样。差别在解析这一步：

```ts
const url = await resourcePort.resolve("Audio/main.mp3");
```

`resolve()` 只要求返回一个当前能用的地址：

- 静态根形态直接拼路径，返回 `/Audio/main.mp3`。
- 加密形态解密之后返回一个短生命周期地址，用完失效。

拿到之前你不知道背后是哪种，也不需要知道。`release(url)` 是给第二种形态留的位——静态地址没有常驻句柄，实现是空的；临时地址在这里回收。

两个失败语义值得记住：

- 解析失败必须抛错，不返回一个坏地址。调用方 fail-closed，宁可不播也不播错。
- 密文形态下磁盘上没有可直引的资源文件，所以引擎里禁止把资源写成静态直引，一切资源都走 `resolve()`。故事里只能写逻辑路径。

## 译文解密归供给侧

`i18nPort.loadOverlayFiles(lang)` 返回的是「路径 + 条目」，没有「明文还是密文」这个字段——它不该由引擎判断。`Lang/en/main.json` 和 `Lang/en/main.json.enc` 对引擎是同一件事：供给方交上来的条目。

所以：

- 你自己写供给时，解密也在你这边做。
- 密文要能解，`project.json` 里得声明 `resourceEncryption: true`。声明了，密文照常解密后参与合并；出现密文却没声明，整次载入按失败处理，引擎发 `i18n-overlay-failed` 并保持原语言。
- 桌面壳的供给在原生层完成收集、读取和解密，交到引擎手上时已经是条目了。

译文文件和故事文件共用同一套资源根和同一个加密声明，不另开一套。

## 存档模式就是安全口径

`SavePort` 只有四个方法，写入带一个模式参数：

```ts
savePort.write(slot, payload, mode);
```

`mode` 取 `SaveMode` 的两个值之一，它同时就是存档的安全口径：

| 模式 | 把存档拷到另一台机器 |
| --- | --- |
| `machine-bound`（默认） | 解不开。密文跟这台机器绑在一起。 |
| `portable` | 能打开，跟着文件走。 |

引擎把 `mode` 原样交给端口，自己不做加解密、也不知道密钥。所以「存档安不安全」在端口实现里定，不在故事里定。

两个跟玩家直接相关的后果：

- 默认档不跨机。想让玩家能手动把进度搬到别的设备，得显式选 `portable`。
- 删档不回退防回档基准。存档带写入计数，删掉较新的档、再回头读一个更旧的档会被拒——不然删档就成了回档的后门。

## 无壳形态能做什么

浏览器里没有「应用自带密钥」这回事：密钥只要进了前端代码，谁都看得到。这不代表网页形态做不了加密，只代表密钥得换个来源——让玩家自己输，或者从你的服务端取。

技术路线是通的：取回密文，用 WebCrypto 解出明文，`URL.createObjectURL()` 造一个临时地址交给 `resolve()`，`release()` 里 revoke 掉。路径和桌面壳形态一样，只是解密在页面里做。

但现状要说清楚：**这条实现现在没有**。加密供给只有桌面壳形态有；Web 形态连未加密的静态根译文供给都还没有——`Lang/` 目录里的译文不会被读，原文直出。上面说的是可行路径，不是现成代码。

编辑器的态度一致：它只开明文工程。故事文件是密文时，它直接告诉你打不开、让你改选明文工程目录——浏览器侧没有密钥，它不猜。

## 扩展碰不到密钥

扩展拿到的上下文只有两样：状态读写（`get` / `set`），和一个只读的故事树。

没有文件系统，没有资源端口，没有存档槽位，也没有密钥。所以：

- 扩展读不了 `Resources/` 下的文件。要资源，得由故事命令去拿。
- 扩展写状态时被强制带上自己的命名空间前缀，改不到别人的键。
- 反过来，状态是扩展读得到的。别把密钥、token 这类东西塞进状态——扩展读得到，回溯和存档也会把它一起带走。

密钥的入口只有平台层那一个，扩展不在这条路上。
